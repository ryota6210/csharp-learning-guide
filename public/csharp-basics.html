01

Program structure

プログラムの構造

C#の命令は基本的に上から下へ実行されます。最初に、もっとも小さなプログラムを見てみましょう。

文（statement）コンピューターへの1つの命令。多くの文は末尾にセミコロン ; を付けます。
● ● ● Program.cs
// 画面に文字を表示する
Console.WriteLine("Hello, C#!");
//

コメント

メモを書くための記号。実行結果には影響しません。

Console.WriteLine

出力命令

丸括弧の中身をコンソールへ表示します。

;

文の終わり

日本語の「。」のように、命令の区切りを示します。

今のC#は短く書ける古い教材では class Program や static void Main が登場します。.NET 6以降では「トップレベル ステートメント」により省略できます。

SETUP最初のプロジェクトを作る

ターミナル
dotnet new console -n HelloCSharp
cd HelloCSharp
dotnet run
  • .cs はC#のソースファイル、.csproj はプロジェクトの設定ファイルです。
  • dotnet build はコンパイル、dotnet run はコンパイルして実行します。
  • C#は大文字と小文字を区別します。Console と console は別の名前です。
従来の Main メソッドで書くと？

トップレベル ステートメントを使わない場合、プログラムの入口は static void Main() です。既存の業務コードや古い教材を読むときに見かけます。

class Program
{
    static void Main()
    {
        Console.WriteLine("Hello");
    }
}

型推論

var を使うと右辺から型を自動判定します。型が消えるわけではなく、この例は int です。

const double Pi = 3.14;

定数

値型・参照型・スコープ

int / bool / struct

値型

変数が値そのものを持ちます。代入すると値がコピーされます。

string / class / array

参照型

オブジェクトを指す参照を持ちます。複数の変数が同じ実体を参照できます。

{ block }

スコープ

変数を使える範囲です。内側で宣言した変数は外側から使えません。

命名の基本

ローカル変数と引数は camelCase、クラス・メソッド・プロパティは PascalCase。意味が伝わる英単語を使い、x のような短い名前は小さな範囲に限定します。

  • 値型の代入は値をコピーし、参照型の代入は参照をコピーする

文字列・入力・型変換

ユーザー入力は文字列として受け取ります。文字列の加工と、安全な数値変換はコンソールアプリの基本です。

Console.Write("名前を入力: ");

if (int.TryParse(input, out int age))
{
    Console.WriteLine($"{name}さんは来年{age + 1}歳");
}
else
{
    Console.WriteLine("年齢は整数で入力してください");
}

EXAMPLE 03 — 分割・整形・結合

Split で分割し、Trim で余分な空白を除き、Join で再び結合します。

format.cs
string input = "  C#, Web,  Game ";
string[] parts = input.Split(',');

for (int i = 0; i < parts.Length; i++)

Console.WriteLine(result);

\n は改行、\t はタブ、\" は引用符です。C# 11以降のraw文字列 """ ... """ はJSONや複数行テキストをそのまま書くときに便利です。

stringは変更不可（immutable）Replace や Trim は元の文字列を変更せず、新しい文字列を返します。大量の結合をループで行う場合は StringBuilder を検討します。

  • 数値変換は失敗を扱える TryParse が基本

04

Operators

演算子

値を計算したり、比べたり、条件を組み合わせたりするための記号です。

+ - * / %

算術演算子

四則演算と、余りを求める %。

== != > < >= <=

比較演算子

2つの値を比較し、結果は bool になります。

&& || !

論理演算子

「かつ」「または」「ではない」で条件を組み合わせます。

● ● ● operators.cs
int price = 1200;
int quantity = 3;
int total = price * quantity;     // 3600

bool canBuy = total <= 5000;     // true
bool isMember = true;
bool hasDiscount = canBuy && isMember;
= と == は別物= は値を入れる「代入」、== は同じか調べる「比較」です。初心者が特に間違えやすいポイントです。
EXAMPLE 04 — 優先順位と複合代入

括弧で計算の意図を明確にする

乗除算は加減算より先です。読者が迷う計算は、優先順位を知っていても括弧を付けます。

precedence.cs
int basePrice = 1000;
int shipping = 300;
int quantity = 2;

int totalA = basePrice + shipping * quantity;   // 1600
int totalB = (basePrice + shipping) * quantity; // 2600

totalB += 200; // totalB = totalB + 200
quantity++;  // quantityを1増やす
totalA: 1600
totalB: 2800
quantity: 3
小数の比較と短絡評価double を == で厳密比較すると計算誤差で意図しない結果になることがあります。また && の右側は左側がtrueのときだけ評価されるため、null確認を先に書けます。
この章の要点
  • 算術・比較・論理演算子は、それぞれ値の計算・比較・条件結合に使う
  • 複雑な式は括弧と中間変数で意図を見せる
  • && と || は短絡評価される
手を動かす

所持金・価格・在庫数を使い、「購入可能か」を1つのbool式で判定してください。

05

Conditions

条件分岐

条件によって実行する処理を切り替えます。「もし〜なら」をコードにしたものです。

条件を調べる
→
true：if を実行
／
false：else を実行
● ● ● condition.cs
int score = 78;

if (score >= 80)
{
    Console.WriteLine("合格：よくできました！");
}
else if (score >= 60)
{
    Console.WriteLine("合格です");
}
else
{
    Console.WriteLine("もう一度挑戦しよう");
}
ブロック波括弧 { } で囲んだ処理のまとまり。インデント（字下げ）をそろえると構造が読みやすくなります。

SWITCH値に応じて分岐する

switch式
string rank = score switch
{
    >= 90 => "A",
    >= 80 => "B",
    >= 60 => "C",
    _     => "D"   // _ はその他すべて
};
  • 単純な二択は三項演算子 条件 ? trueの値 : falseの値 でも書けます。
  • && と || は左から評価し、結果が確定した時点で残りを評価しない「短絡評価」を行います。
EXAMPLE 05 — ガード節

異常な条件を先に終わらせる

ネストを深くせず、読者が「正常な流れ」を追いやすくする書き方です。

guard-clause.cs
string GetTicketType(int age)
{
    if (age < 0)
        throw new ArgumentOutOfRangeException(nameof(age));

    if (age < 6) return "無料";
    if (age < 18) return "子ども";
    if (age >= 65) return "シニア";
    return "大人";
}
GetTicketType(4) → 無料
GetTicketType(20) → 大人
GetTicketType(70) → シニア
条件の順番で結果が変わるelse if は最初にtrueになったブロックだけを実行します。広い条件を先に書くと、後の細かい条件へ到達しません。境界値（0、59、60、79、80など）を必ず確認します。
この章の要点
  • 二択・段階的判定・値による分岐で if と switch を使い分ける
  • 異常条件を先に返すガード節でネストを浅くする
  • 境界値を例にして条件漏れや重複を確認する
手を動かす

気温を受け取り、「寒い・快適・暑い」を返すメソッドを作り、境界値も試してください。

06

Loops

繰り返し

同じ処理を何度も行うときはループを使います。回数が決まっているなら for、集合を順に読むなら foreach が便利です。

for：回数で繰り返す
for (int i = 1; i <= 3; i++)
{
    Console.WriteLine($"{i}回目");
}
foreach：要素を順に読む
string[] colors = { "赤", "青", "緑" };

foreach (string color in colors)
{
    Console.WriteLine(color);
}
while ループ条件が true の間だけ繰り返します。条件が永遠に true だと無限ループになるため注意しましょう。
while・break・continue
int number = 0;
while (number < 10)
{
    number++;
    if (number % 2 != 0) continue; // 奇数は飛ばす
    if (number > 6) break;       // ループを終了
    Console.WriteLine(number);     // 2, 4, 6
}
EXAMPLE 06 — 二重ループ

九九の一部を表形式で出す

外側のループが行、内側のループが列を担当します。

nested-loop.cs
for (int row = 1; row <= 3; row++)
{
    for (int column = 1; column <= 3; column++)
        Console.Write($"{row * column,3}");

    Console.WriteLine();
}
  1  2  3
  2  4  6
  3  6  9
off-by-one（1つずれる）に注意要素数が Length の配列で使える最大インデックスは Length - 1 です。通常は i < items.Length と書き、<= にしません。
この章の要点
  • 回数なら for、全要素なら foreach、条件継続なら while
  • break は終了、continue は次の繰り返しへ進む
  • 無限ループと境界の1つずれを重点的に確認する

実務でよく使う引数の機能

EXAMPLE 07 — 小さな責務へ分ける

料金計算と表示を別のメソッドにする

{

この章の要点

  • 1つの役割に絞り、副作用の少ない計算メソッドを作る
  • 引数と戻り値の型を、メソッドの契約として考える

EXAMPLE 09 — 単語の出現回数

Dictionaryで集計する

単語をキー、出現回数を値にします。未知のキーを初期化してから加算します。

word-count.cs
string[] words = { "C#", "Web", "C#", "Game" };
Dictionary<string, int> counts = new();

foreach (string word in words)
{
    if (!counts.ContainsKey(word)) counts[word] = 0;
    counts[word]++;
}

Object-oriented programming

継承とインターフェイス

異なるクラスを共通の型として扱う仕組みがポリモーフィズムです。インターフェイスは「できること」の契約を表します。

interface とポリモーフィズム
INotifier notifier = new EmailNotifier();
notifier.Send("処理が完了しました");

interface INotifier
{
    void Send(string message);
}

class EmailNotifier : INotifier
{
    public void Send(string message)
        => Console.WriteLine($"Email: {message}");
}
  • カプセル化：内部の状態を隠し、公開メソッド経由で安全に操作します。
  • 継承：Dog : Animal のように既存クラスを拡張します。virtual / override で動作を差し替えられます。
  • インターフェイス：実装を持たない共通契約を定義し、差し替えやテストを容易にします。
継承よりコンポジションも検討「〜である（is-a）」が明確なら継承、「〜を持つ（has-a）」なら別オブジェクトを組み合わせる設計が自然です。
EXAMPLE 11 — 実装を差し替える

同じ契約を別クラスで実装する

呼び出し側は具体的な通知方法を知らず、INotifier だけに依存します。

polymorphism.cs
List<INotifier> notifiers = new()
{
    new EmailNotifier(),
    new ConsoleNotifier()
};

foreach (INotifier item in notifiers)
    item.Send("完了");
Email: 完了
Console: 完了
深い継承階層を作らない基底クラスの変更が多くの派生クラスへ影響します。共通コードがあるという理由だけで継承せず、契約はinterface、処理の再利用は小さな部品の組み合わせも検討します。
この章の要点
  • 継承はis-a、コンポジションはhas-aの関係
  • interfaceを介すと実装の差し替えとテストが容易になる
  • ポリモーフィズムにより異なる実装を共通の型で扱える

null は「参照先がない」状態です。C#のnullable参照型は、nullの可能性をコンパイル時に知らせてくれます。

    Console.WriteLine(score);

!「nullではない」とコンパイラへ伝える。乱用は避ける
基本方針

Exceptions

例外処理

実行中に起こる想定外の問題を「例外」と呼びます。try-catch で安全に受け止められます。

● ● ● exception.cs

{
    int number = int.Parse("abc");

}
まずはエラー文を読むエラーは「失敗」ではなく、直す場所を教えるヒントです。例外の種類・メッセージ・行番号の3つを確認しましょう。
  • catch (Exception ex) で情報を受け取り、ex.Message やスタックトレースを記録できます。

T Last<T>(IReadOnlyList<T> items)

Asynchronous programming

async / await

通信やファイル読み書きの待ち時間に、スレッドを塞がないための仕組みです。処理が速くなるのではなく、待機中も他の仕事を進められるようにします。

非同期メソッド
await ShowMessageAsync();

async Task ShowMessageAsync()
{
    Console.WriteLine("待機開始");
    await Task.Delay(1000);
    Console.WriteLine("完了");
}

async Task<string> DownloadAsync(HttpClient client)
    => await client.GetStringAsync("https://example.com");
  • 戻り値なしは Task、結果ありは Task<T>。async void は原則イベントハンドラーだけにします。
  • await できる処理は、呼び出し側も通常 async へ伝播します。
  • .Result や .Wait() は停止やデッドロックの原因になるため、await を優先します。
  • 長時間処理は CancellationToken を受け取り、キャンセル可能にします。
EXAMPLE 17 — 並行して待つ

独立した非同期処理をTask.WhenAllでまとめる

1つずつawaitする必要がない処理は同時に開始し、全完了を待てます。

when-all.cs
Task<string> userTask = LoadUserAsync();
Task<string> newsTask = LoadNewsAsync();

await Task.WhenAll(userTask, newsTask);
Console.WriteLine(await userTask);
Console.WriteLine(await newsTask);
並行と並列は同じではないasync/awaitは主にI/O待機を効率化します。CPU負荷の高い処理を速くする仕組みではありません。大量のタスクを無制限に開始せず、APIやファイルの同時実行数を制御します。
この章の要点
  • awaitはTaskの完了を非同期に待つ
  • 独立した処理はWhenAll、順序が必要なら順番にawaitする
  • キャンセル・タイムアウト・例外の扱いも呼び出し側まで設計する

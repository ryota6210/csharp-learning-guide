Program structure

プログラムの構造

C#の命令は基本的に上から下へ実行されます。最初に、もっとも小さなプログラムを見てみましょう。

文（statement）コンピューターへの1つの命令。多くの文は末尾にセミコロン ; を付けます。
● ● ● Program.cs
// 画面に文字を表示する
Console.WriteLine("Hello, C#!");
//

コメント

メモを書くための記号。実行結果には影響しません。

Console.WriteLine

出力命令

丸括弧の中身をコンソールへ表示します。

;

文の終わり

日本語の「。」のように、命令の区切りを示します。

今のC#は短く書ける古い教材では class Program や static void Main が登場します。.NET 6以降では「トップレベル ステートメント」により省略できます。

SETUP最初のプロジェクトを作る

ターミナル
dotnet new console -n HelloCSharp
cd HelloCSharp
dotnet run
  • .cs はC#のソースファイル、.csproj はプロジェクトの設定ファイルです。
  • dotnet build はコンパイル、dotnet run はコンパイルして実行します。
  • C#は大文字と小文字を区別します。Console と console は別の名前です。
従来の Main メソッドで書くと？

トップレベル ステートメントを使わない場合、プログラムの入口は static void Main() です。既存の業務コードや古い教材を読むときに見かけます。

class Program
{
    static void Main()
    {
        Console.WriteLine("Hello");
    }
}

Strings, input & conversion

文字列・入力・型変換

ユーザー入力は文字列として受け取ります。文字列の加工と、安全な数値変換はコンソールアプリの基本です。

● ● ● input.cs
Console.Write("名前を入力: ");
string? name = Console.ReadLine();

Console.Write("年齢を入力: ");
string? input = Console.ReadLine();

if (int.TryParse(input, out int age))
{
    Console.WriteLine($"{name}さんは来年{age + 1}歳");
}
else
{
    Console.WriteLine("年齢は整数で入力してください");
}
書き方用途例
$"...{value}..."文字列補間値を読みやすく埋め込む
@"C:\path"逐語的文字列バックスラッシュをそのまま扱う
"A" + "B"文字列結合"AB"
text.Length文字数"C#".Length は2
Trim / Replace / Split加工空白除去・置換・分割
入力には TryParse を優先int.Parse は変換できない文字で例外になります。TryParse なら成否を bool で受け取れるため、安全に分岐できます。

Operators

演算子

値を計算したり、比べたり、条件を組み合わせたりするための記号です。

+ - * / %

算術演算子

四則演算と、余りを求める %。

== != > < >= <=

比較演算子

2つの値を比較し、結果は bool になります。

&& || !

論理演算子

「かつ」「または」「ではない」で条件を組み合わせます。

● ● ● operators.cs
int price = 1200;
int quantity = 3;

bool canBuy = total <= 5000;     // true

bool hasDiscount = canBuy && isMember;
= と == は別物= は値を入れる「代入」、== は同じか調べる「比較」です。初心者が特に間違えやすいポイントです。

Conditions

条件分岐

条件によって実行する処理を切り替えます。「もし〜なら」をコードにしたものです。

条件を調べる
→
true：if を実行
／
false：else を実行
● ● ● condition.cs
int score = 78;

if (score >= 80)
{
    Console.WriteLine("合格：よくできました！");
}
else if (score >= 60)
{
    Console.WriteLine("合格です");
}
else
{
    Console.WriteLine("もう一度挑戦しよう");
}
ブロック波括弧 { } で囲んだ処理のまとまり。インデント（字下げ）をそろえると構造が読みやすくなります。

SWITCH値に応じて分岐する

switch式
string rank = score switch
{
    >= 90 => "A",
    >= 80 => "B",
    >= 60 => "C",
    _     => "D"   // _ はその他すべて
};
  • 単純な二択は三項演算子 条件 ? trueの値 : falseの値 でも書けます。
  • && と || は左から評価し、結果が確定した時点で残りを評価しない「短絡評価」を行います。
06

Loops

繰り返し

同じ処理を何度も行うときはループを使います。回数が決まっているなら for、集合を順に読むなら foreach が便利です。

for：回数で繰り返す
for (int i = 1; i <= 3; i++)
{
    Console.WriteLine($"{i}回目");
}
foreach：要素を順に読む
string[] colors = { "赤", "青", "緑" };

foreach (string color in colors)
{
    Console.WriteLine(color);
}
while ループ条件が true の間だけ繰り返します。条件が永遠に true だと無限ループになるため注意しましょう。
while・break・continue
int number = 0;
while (number < 10)
{
    number++;
    if (number % 2 != 0) continue; // 奇数は飛ばす
    if (number > 6) break;       // ループを終了
    Console.WriteLine(number);     // 2, 4, 6
}

Methods

メソッド

処理に名前を付けて再利用できるようにしたものです。「入力を受け取り、処理し、結果を返す」小さな部品として考えます。

return

実務でよく使う引数の機能

省略可能・名前付き・オーバーロード

Console.WriteLine(Greet(suffix: "先生", name: "鈴木"));

11

Object-oriented programming

継承とインターフェイス

異なるクラスを共通の型として扱う仕組みがポリモーフィズムです。インターフェイスは「できること」の契約を表します。

interface とポリモーフィズム
INotifier notifier = new EmailNotifier();
notifier.Send("処理が完了しました");

interface INotifier
{
    void Send(string message);
}

class EmailNotifier : INotifier
{
    public void Send(string message)
        => Console.WriteLine($"Email: {message}");
}
  • カプセル化：内部の状態を隠し、公開メソッド経由で安全に操作します。
  • 継承：Dog : Animal のように既存クラスを拡張します。virtual / override で動作を差し替えられます。
  • インターフェイス：実装を持たない共通契約を定義し、差し替えやテストを容易にします。
継承よりコンポジションも検討「〜である（is-a）」が明確なら継承、「〜を持つ（has-a）」なら別オブジェクトを組み合わせる設計が自然です。
12

Nullability

nullとnullable

null は「参照先がない」状態です。C#のnullable参照型は、nullの可能性をコンパイル時に知らせてくれます。

nullを安全に扱う
string? nickname = Console.ReadLine();

int length = nickname?.Length ?? 0;
string displayName = nickname ?? "ゲスト";

int? optionalScore = null; // nullable値型
if (optionalScore is int score)
    Console.WriteLine(score);
記号意味
T?nullを許可する型
?.nullなら処理を止めてnullを返す
??nullのとき代わりの値を使う
!「nullではない」とコンパイラへ伝える。乱用は避ける
基本方針

可能ならnullを作らない設計にし、必要な場所だけ ? を付けます。警告を ! で消す前に、nullになる経路を確認しましょう。

13

Exceptions

例外処理

実行中に起こる想定外の問題を「例外」と呼びます。try-catch で安全に受け止められます。

● ● ● exception.cs
try
{
    int number = int.Parse("abc");
}
catch (FormatException)
{
    Console.WriteLine("数字を入力してください");
}
まずはエラー文を読むエラーは「失敗」ではなく、直す場所を教えるヒントです。例外の種類・メッセージ・行番号の3つを確認しましょう。
  • catch (Exception ex) で情報を受け取り、ex.Message やスタックトレースを記録できます。
  • finally は成功・失敗にかかわらず実行され、後始末に使います。
  • throw new ArgumentException(...) で不正な状態を呼び出し元へ通知できます。
  • 入力ミスのように予想できる失敗は、例外より TryParse などで扱います。
14

Language integrated query

LINQでデータを操作する

LINQはコレクションの絞り込み、変換、並べ替え、集計を統一した書き方で行う機能です。元のコレクションを変更せず、新しい結果を作る操作が中心です。

メソッド構文のLINQ
List<int> scores = new() { 72, 95, 81, 58 };

List<string> labels = scores
    .Where(score => score >= 80)
    .OrderByDescending(score => score)
    .Select(score => $"{score}点")
    .ToList();

double average = scores.Average();
int first = scores.FirstOrDefault(score => score >= 90);
メソッド役割
Where条件に合う要素を絞り込む
Select各要素を別の形へ変換する
OrderBy並べ替える
Any / All存在・全件の条件を調べる
Count / Sum / Average件数・合計・平均を集計する
FirstOrDefault最初の要素、なければ既定値を返す
遅延実行多くのLINQ操作は、foreach や ToList() で列挙されるまで実行されません。結果をその時点で固定したいなら ToList() を使います。

Generics

ジェネリック

型を後から指定できる部品を作る仕組みです。型安全性を保ったまま、同じロジックをさまざまな型で再利用できます。

ジェネリックメソッドと型制約
T Last<T>(IReadOnlyList<T> items)
{
    if (items.Count == 0)
        throw new ArgumentException("要素が必要です");

    return items[^1]; // ^1 は末尾
}

string lastName = Last(new[] { "Aoi", "Sora" });

class Repository<T> where T : class
{
    private readonly List<T> items = new();
    public void Add(T item) => items.Add(item);
}
  • <T> のTは型パラメーター。呼び出し時に int や string などへ決まります。
  • where T : class のような型制約で、使える型や操作を限定できます。
  • List<T>、Dictionary<TKey,TValue>、Task<T> もジェネリック型です。

処理そのものを値として渡す仕組みです。LINQの条件、ボタンのクリック、処理完了通知などに使われます。

処理を変数や引数にする
Func<int, int, int> add = (a, b) => a + b;
Action<string> log = message => Console.WriteLine(message);
Predicate<int> isEven = number => number % 2 == 0;

log($"答え: {add(2, 3)}");

class Downloader
{
    public event Action? Completed;
    public void Finish() => Completed?.Invoke();
}
Func<...>

値を返す処理

最後の型引数が戻り値です。

Action<...>

値を返さない処理

void 相当の処理を表します。

event

発生を通知

発行側と購読側を疎結合にします。

17

Asynchronous programming

async / await

通信やファイル読み書きの待ち時間に、スレッドを塞がないための仕組みです。処理が速くなるのではなく、待機中も他の仕事を進められるようにします。

非同期メソッド
await ShowMessageAsync();

async Task ShowMessageAsync()
{
    Console.WriteLine("待機開始");
    await Task.Delay(1000);
    Console.WriteLine("完了");
}

async Task<string> DownloadAsync(HttpClient client)
    => await client.GetStringAsync("https://example.com");
  • 戻り値なしは Task、結果ありは Task<T>。async void は原則イベントハンドラーだけにします。
  • await できる処理は、呼び出し側も通常 async へ伝播します。
  • .Result や .Wait() は停止やデッドロックの原因になるため、await を優先します。
  • 長時間処理は CancellationToken を受け取り、キャンセル可能にします。
